Visual Pedagogy

Why text explanations aren't enough

Go is deliberately simple in syntax, but its runtime behavior (memory allocation, slice headers, channel locks, scheduling) is full of subtle gotchas.

🧠
Backing Arrays, Not Abstractions

A slice is a 3-word struct pointing to an array. When two slices point to the same memory, mutations silently bleed over. We show the exact memory addresses.

⚡
Lock-Free Concurrency

Understand how unbuffered channel handshakes force synchronized rendezvous between goroutines, and how buffer queues hold items without blocking.

🎯
The Nil Interface Trap

Why does err != nil return true even when the error pointer is nil? Seeing the two-word (type, value) interface tuple makes it crystal clear.

🔍
Real Captured Output

Every code sample has its real compiler stdout captured verbatim. Panic stack traces, deadlocks, and benchmark numbers are 100% genuine.

Checkpoint Quiz Test your Go intuition
You create a slice a := []int{1, 2, 3}, then take a sub-slice b := a[:2] and run b[0] = 99. What happens to a[0]?
Correct! In Go, sub-slicing a[:2] creates a new 24-byte SliceHeader struct containing {Data: ptr, Len: 2, Cap: 3}. The pointer points directly into the same backing array as a. Modifying b[0] mutates that shared memory, so a[0] also reads 99.
