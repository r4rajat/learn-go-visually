Hash Tables & Go Runtime Maps

Inside Go's runtime map: `hmap` and 8-slot `bmap` buckets. Top-hash byte comparisons, overflow buckets for collision chaining, and incremental rehashing.

1. Concept & Go Memory Architecture

In Go, algorithmic performance and memory efficiency depend heavily on whether data structures use value semantics (contiguous stack allocations) or heap pointer indirection. Observe the memory layout below:

Go Runtime hmap Architecture: ┌──────────┐ Buckets Array ([]bmap): │ hmap │ ┌──────────────────────────────────────────────┐ │ count │ │ Bucket 0: [tophash: 8B][keys: 8][vals: 8][overflow] │ B=3 ├───► ├──────────────────────────────────────────────┤ │ buckets │ │ Bucket 1: [tophash: 8B][keys: 8][vals: 8][overflow] └──────────┘ └──────────────────────────────────────────────┘
2. Canonical Problem

🎯 Problem: Group Anagrams (LeetCode 49)

Given an array of strings strs, group the anagrams together in any order.

Key Algorithmic Insight: Use a character count array [26]byte as the map key. Because arrays are comparable values in Go, [26]byte works directly as a map key with zero heap string allocations!
3. Intuition & Mental Model

Two words are anagrams if they have the exact same character frequencies. Sorting each string takes O(K log K). In Go, array types like [26]byte are comparable values that can be used directly as map keys! We count characters into a [26]byte array with zero heap string allocations.

🪜 Step-by-Step Algorithmic Strategy

1
Create a map[ [26]byte ][]string to group anagrams.
2
For each string, create a [26]byte array and count letter occurrences.
3
Append the word to map[count].
4
Collect all values from the map into a 2D slice [][]string.
4. Structured Pseudocode

Before looking at Go syntax, study the language-agnostic logic. Trace this mentally with sample inputs:

Algorithm Pseudocode Language Independent 
FUNCTION groupAnagrams(strs):
    groups = MAP of [26]byte -> LIST of strings

    FOR EACH word IN strs:
        countArray = ARRAY_OF_26_ZEROS()
        FOR EACH char IN word:
            countArray[char - 'a']++
        APPEND word TO groups[countArray]

    RETURN ALL_LISTS_FROM(groups)
⚠️ Common Pitfalls & Edge Cases
Using `[]byte` (slice) as a map key, which causes a Go compile error because slices are not comparable! Fixed arrays `[26]byte` are comparable and valid map keys.

day08_hash_tables_and_go_runtime_maps.go 
package main

import "fmt"

func groupAnagrams(strs []string) [][]string {
	// [26]byte is a value type in Go, so it can be a map key directly!
	groups := make(map[[26]byte][]string)

	for _, s := range strs {
		var count [26]byte
		for i := 0; i < len(s); i++ {
			count[s[i]-'a']++
		}
		groups[count] = append(groups[count], s)
	}

	res := make([][]string, 0, len(groups))
	for _, g := range groups {
		res = append(res, g)
	}
	return res
}

func main() {
	strs := []string{"eat", "tea", "tan", "ate", "nat", "bat"}
	fmt.Println("Grouped:", groupAnagrams(strs))
}
