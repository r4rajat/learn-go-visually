Day 14 Phase 5 · Patterns Hard O(amount × n) Time O(amount) Space

Dynamic Programming

Overlapping subproblems and optimal substructure. Top-down memoization with maps vs. bottom-up tabulation with slices. Space optimization and 1D rolling array DP.

1. Concept & Go Memory Architecture

In Go, algorithmic performance and memory efficiency depend heavily on whether data structures use value semantics (contiguous stack allocations) or heap pointer indirection. Observe the memory layout below:

Coin Change DP Table (amount = 5, coins = [1, 2]): Amount: 0 1 2 3 4 5 dp: [ 0 ][ 1 ][ 1 ][ 2 ][ 2 ][ 3 ] dp[i] = min(dp[i], dp[i - coin] + 1)
2. Canonical Problem

🎯 Problem: Coin Change (LeetCode 322)

You are given an integer array coins and an integer amount. Return the fewest number of coins that you need to make up that amount.

Key Algorithmic Insight: Define dp[i] as the minimum coins to make amount i. For each coin, if i >= coin, dp[i] = min(dp[i], dp[i-coin] + 1).
3. Intuition & Mental Model

Greedy coin change fails for non-standard coin denominations (e.g. coins=[1,3,4], amount=6; greedy picks 4+1+1=3 coins, but optimal is 3+3=2 coins). Dynamic programming solves this by computing the answer for every sub-amount from 0 up to amount.

🪜 Step-by-Step Algorithmic Strategy

1
Create a dp slice of size amount + 1, filled with amount + 1 (impossible high value).
2
Base case: dp[0] = 0 (0 coins needed to make amount 0).
3
For each sub-amount i from 1 to amount, check every coin c.
4
If i >= c, dp[i] = min(dp[i], dp[i - c] + 1).
5
If dp[amount] > amount, return -1 (impossible); otherwise return dp[amount].
4. Structured Pseudocode

Before looking at Go syntax, study the language-agnostic logic. Trace this mentally with sample inputs:

Algorithm Pseudocode Language Independent 
FUNCTION coinChange(coins, amount):
    dp = ARRAY(size = amount + 1, initial = amount + 1)
    dp[0] = 0

    FOR i FROM 1 TO amount:
        FOR EACH coin IN coins:
            IF i >= coin:
                dp[i] = min(dp[i], dp[i - coin] + 1)

    IF dp[amount] > amount: RETURN -1
    RETURN dp[amount]
⚠️ Common Pitfalls & Edge Cases
Initializing dp array with 0 or math.MaxInt32 (which causes integer overflow when adding + 1). Use `amount + 1` as the sentinel upper bound.

day14_dynamic_programming.go 
package main

import "fmt"

func coinChange(coins []int, amount int) int {
	dp := make([]int, amount+1)
	// Initialize with impossible high value
	for i := 1; i <= amount; i++ {
		dp[i] = amount + 1
	}
	dp[0] = 0

	for i := 1; i <= amount; i++ {
		for _, c := range coins {
			if i >= c && dp[i-c]+1 < dp[i] {
				dp[i] = dp[i-c] + 1
			}
		}
	}

	if dp[amount] > amount {
		return -1
	}
	return dp[amount]
}

func main() {
	fmt.Println("Min coins:", coinChange([]int{1, 2, 5}, 11)) // 3 (5 + 5 + 1)
}
