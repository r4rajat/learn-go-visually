Divide & Conquer with Goroutines

The Divide, Conquer, Combine paradigm. Harnessing Go's concurrency primitives: running independent subproblems in lightweight goroutines and combining results via channels.

1. Concept & Visual Architecture

In Go, algorithmic efficiency and performance stem from understanding memory layout, pointer indirection, and value semantics. Study the visual representation below:

2. Canonical Problem

🎯 Problem: Concurrent Parallel Merge Sort in Go

Sort an integer slice concurrently by delegating recursive left and right sub-arrays to separate goroutines bounded by a recursion depth.

Key Algorithmic Insight: Unbounded goroutine creation causes scheduler overhead. Pass a depth budget: when depth <= 0, fall back to sequential sort.
3. Intuition & Mental Model

Divide and conquer splits problems into independent sub-tasks. In Go, independent sub-arrays can be sorted concurrently in separate lightweight goroutines, communicating back via channels. A recursion depth limit prevents creating millions of goroutines for tiny slices.

🪜 Step-by-Step Algorithmic Strategy

1
Base case: if len(arr) <= 1, return arr.
2
If depth <= 0, fall back to sequential merge sort.
3
Spawn two goroutines to sort left and right halves concurrently.
4
Receive sorted slices from channels.
5
Merge the two sorted halves in linear O(n) time.
4. Structured Pseudocode

Before looking at Go syntax, study the language-agnostic logic. Trace this mentally with sample inputs:

Algorithm Pseudocode Language Independent 
FUNCTION ConcurrentMergeSort(arr, depth):
    IF len(arr) <= 1: RETURN arr
    IF depth <= 0: RETURN sequentialMergeSort(arr)
    mid = len(arr) / 2

    SPAWN GOROUTINE: leftChan <- ConcurrentMergeSort(arr[:mid], depth - 1)
    SPAWN GOROUTINE: rightChan <- ConcurrentMergeSort(arr[mid:], depth - 1)

    left = <-leftChan
    right = <-rightChan
    RETURN merge(left, right)
⚠️ Common Pitfalls & Edge Cases
Spawning goroutines without a depth limit. Goroutines are lightweight (2KB), but spawning 50,000 goroutines causes CPU cache thrashing.

day26_divide_and_conquer_with_goroutines.go 
package main

import "fmt"

func merge(left, right []int) []int {
	res := make([]int, 0, len(left)+len(right))
	i, j := 0, 0
	for i < len(left) && j < len(right) {
		if left[i] <= right[j] {
			res = append(res, left[i])
			i++
		} else {
			res = append(res, right[j])
			j++
		}
	}
	res = append(res, left[i:]...)
	res = append(res, right[j:]...)
	return res
}

func ConcurrentMergeSort(arr []int, depth int) []int {
	if len(arr) <= 1 {
		return arr
	}
	mid := len(arr) / 2

	if depth <= 0 {
		left := ConcurrentMergeSort(arr[:mid], 0)
		right := ConcurrentMergeSort(arr[mid:], 0)
		return merge(left, right)
	}

	leftChan := make(chan []int)
	rightChan := make(chan []int)

	go func() { leftChan <- ConcurrentMergeSort(arr[:mid], depth-1) }()
	go func() { rightChan <- ConcurrentMergeSort(arr[mid:], depth-1) }()

	left := <-leftChan
	right := <-rightChan
	return merge(left, right)
}

func main() {
	data := []int{38, 27, 43, 3, 9, 82, 10}
	sorted := ConcurrentMergeSort(data, 2)
	fmt.Println("Sorted:", sorted) // [3 9 10 27 38 43 82]
}
