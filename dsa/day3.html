Linked Lists with Go Generics

Pointers in Go, constructing generic Singly and Doubly Linked Lists using `Node[T any]`, sentinel dummy nodes to eliminate edge-case nil checks, and Floyd's cycle detection.

1. Concept & Go Memory Architecture

In Go, algorithmic performance and memory efficiency depend heavily on whether data structures use value semantics (contiguous stack allocations) or heap pointer indirection. Observe the memory layout below:

Singly Linked List: ┌──────┬──────┐ ┌──────┬──────┐ ┌──────┬──────┐ │Val: 1│ Next ┼───►│Val: 2│ Next ┼───►│Val: 3│ nil │ └──────┴──────┘ └──────┴──────┘ └──────┴──────┘ Head Tail
2. Canonical Problem

🎯 Problem: Reverse Linked List & Detect Cycle (LeetCode 206 & 141)

1. Reverse a singly linked list in-place in O(n) time and O(1) space. 2. Detect if a linked list contains a cycle using two pointers.

Key Algorithmic Insight: For reversal, maintain prev, curr, next pointers and redirect curr.Next = prev. For cycle detection, slow moves 1 step and fast moves 2 steps; they meet if and only if a cycle exists.
3. Intuition & Mental Model

Unlike arrays where elements sit next to each other in memory, linked list nodes are scattered across the heap and connected by pointers. To reverse a list, we don't move data—we flip the direction of the arrows. We use three pointers: 'prev' (what came before), 'curr' (where we are), and 'nextTemp' (saving what comes next so we don't break the chain).

🪜 Step-by-Step Algorithmic Strategy

1
Initialize prev pointer to nil and curr pointer to head.
2
While curr is not nil, temporarily store curr.Next in nextTemp.
3
Reverse the link: set curr.Next = prev.
4
Shift prev forward to curr.
5
Shift curr forward to nextTemp.
6
When curr hits nil, prev is pointing to the new head of the reversed list.
4. Structured Pseudocode

Before looking at Go syntax, study the language-agnostic logic. Trace this mentally with sample inputs:

Algorithm Pseudocode Language Independent 
FUNCTION reverseList(head):
    prev = nil
    curr = head

    WHILE curr IS NOT nil:
        nextTemp = curr.Next    // Save next node before severing pointer
        curr.Next = prev        // Reverse direction of pointer
        prev = curr             // Move prev one step forward
        curr = nextTemp         // Move curr one step forward

    RETURN prev                 // prev is the new head
⚠️ Common Pitfalls & Edge Cases
Severing `curr.Next = prev` without first saving `nextTemp = curr.Next` (losing the rest of the list forever). Forgetting to handle an empty list (head == nil) or single-node list.

day03_linked_lists_with_go_generics.go 
package main

import "fmt"

type ListNode[T any] struct {
	Val  T
	Next *ListNode[T]
}

// ReverseList reverses a linked list in-place
func ReverseList[T any](head *ListNode[T]) *ListNode[T] {
	var prev *ListNode[T]
	curr := head
	for curr != nil {
		nextTemp := curr.Next
		curr.Next = prev
		prev = curr
		curr = nextTemp
	}
	return prev
}

// HasCycle detects loops using Floyd's Tortoise and Hare
func HasCycle[T any](head *ListNode[T]) bool {
	slow, fast := head, head
	for fast != nil && fast.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
		if slow == fast {
			return true
		}
	}
	return false
}

func main() {
	n3 := &ListNode[int]{Val: 3, Next: nil}
	n2 := &ListNode[int]{Val: 2, Next: n3}
	n1 := &ListNode[int]{Val: 1, Next: n2}

	rev := ReverseList(n1)
	for curr := rev; curr != nil; curr = curr.Next {
		fmt.Printf("%d -> ", curr.Val)
	}
	fmt.Println("nil") // 3 -> 2 -> 1 -> nil
}
